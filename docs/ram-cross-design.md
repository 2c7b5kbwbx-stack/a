# 決算またぎ判定システム「ram cross」設計書

## 目的
市場が織り込んだ「期待値」と実際の業績との**ギャップ（歪み）**を突き、決算またぎでのリスクリワードを最大化する。完全自動化（クーロン等の定期実行）は採用せず、土日の事前処理と決算当日の直前確認を分離することで、市場の織り込みの罠を回避する。

## システム構成
- **言語**: Python 3.11+
- **データ基盤**: J-Quants API (Lightプラン) + Notion API
- **LLM**: Anthropic Claude API (フェーズ2の定性解析)
- **ストレージ**: ローカルファイル (CSV/JSON)、`.env` でシークレット管理

### Lightプランの制約
ヒストリカルデータは直近2年分（=8四半期）に制限される。設計上は「過去N四半期」をパラメータ化し、後でプラン変更しても切替可能とする。

## フェーズ1: 定量スクリーニング・基礎スコア算出（実行: 土日）

### ① 四半期進捗と季節性の評価
- **入力**: J-Quants `/fins/statements` から過去8四半期の業績
- **判定**: 単純な進捗率（25%）ではなく、「過去の当該四半期の平均進捗率」をどれだけ上回っているかをスコア化
- **目的**: 季節偏重を無視した甘い判定を排除

### ② バリュエーションと成長性 (PEG判定)
- **入力**: J-Quants の現在PER、今期予想EPS、前期実績EPS
- **判定**:
  - PEGレシオ < 1.0
  - 現在PER < ヒストリカルPER中央値
  - 配当利回り > 過去平均 → 下値支持として加点
- **目的**: 業界平均との単純比較による「偽の割安銘柄」を排除

### ③ 修正癖の定量化（サプライズ予測）
- **入力**: J-Quants `/fins/announcement` および TDnet 開示履歴
- **判定**: 「業績予想の修正」と「決算発表」の日時差から、決算直前に上方修正を出す確率をフラグ化
- **目的**: 定性的な「修正しがち」を数値化

### ④ 過去メモのダイレクト統合
- **入力**: Notion API（テキストフィールドのみ）
- **処理**: 対象銘柄の過去決算メモをスコアリングコンテキストに統合

---

## フェーズ2: 定性データ解析・期待値ペナルティ判定（実行: 土日）

### ① アナリストレポートによる「期待値ペナルティ」判定（逆張り指標）
- **対象レポート**: みずほ、モルガン・スタンレーMUFG、東海東京、岩井コスモ、SMBC
- **処理**: Claude API にレポートテキストを渡し、JSON で以下フラグを強制出力
  - `buyback_expected: bool`
  - `dividend_increase_expected: bool`
  - `sentiment_score: float` (0.0〜1.0)
- **判定**: フラグTrue または センチメント高すぎ → **市場期待が膨らみすぎ＝決算ハードルが高すぎる** とみなし大幅減点（ペナルティ）

### ② 決算説明資料からの「先行KPI」抽出
- **入力**: 過去の決算説明資料 PDF
- **処理**: Claude API で「受注残」「ARR」等の非財務KPIを抽出
- **判定**: 前四半期からの成長率を加点要素

### ③ リスクファクターの差分（Diff）検知
- **処理**: 前回 vs 今回のレポート/説明資料を比較
- **判定**: ネガティブ差分（為替注視、採用鈍化等）→ 来期ガイダンス弱気の前兆として減点

---

## 運用フロー: 決算当日の直前チェック（実行: 決算日 14:30〜14:50）

土日のフェーズ1・2を経た「監視候補リスト」に対し、最終エントリー可否を判定する**最重要の足切り**。

- **処理**: 決算発表直前の日足チャート（現在値）を確認
- **絶対ルール**: 決算前の数日〜数週間で株価が異常急騰（例: 10%以上）している場合、土日のスコアがどれほど優秀でも**「期待の織り込み済み」としてエントリー見送り**
